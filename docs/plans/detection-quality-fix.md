## Idea
Mengatasi tiga kelas masalah deteksi YOLO di ServiceAPDBackend.py: (1) FALSE POSITIVE half-body — saat orang cuma kelihatan kepala/dada, vest pasti tidak terdeteksi sehingga logic default-violation di line 670-672 (`if explicit_no_helmet or not has_helmet: missing.append("helmet")`) selalu memicu pelanggaran palsu. (2) FLICKER — satu frame meleset bisa langsung trigger MQTT publish karena tidak ada temporal smoothing; `last_violations` di line 806/836/840 hanya buffer 1-frame untuk frame-skip carryover, bukan smoothing window. (3) PERFORMANCE — model load FP32 (`load_model` 369-390), tidak ada FP16, frame-skip statis (`DETECT_EVERY_N` line 809 ditentukan sekali, tidak adaptif), dan `COLOR_SAFE` di line 274 didefinisikan tapi tidak pernah dipakai untuk drawing.

BONUS BUG yang harus dibereskan sekalian: settings UI di /settings (web-dashboard/src/app/settings/page.tsx:521-559) menyimpan slider confidenceThreshold + personConfidence ke /api/settings tapi Python TIDAK PERNAH baca endpoint itu — slider mati. Operator yang ubah threshold dari dashboard ngerasa berfungsi padahal tidak.

Pendekatan: tiga lapis filter (bbox completeness → conditional class check → temporal smoothing) + dua perf win (FP16, adaptive skip) + fix wiring settings + fix safe-bbox drawing. Pure helpers diekstrak supaya bisa di-pytest tanpa mock cv2/YOLO (sesuai precedent di tests/test_servicebackend_skip_observation.md). Default behavior dipertahankan saat bbox completeness CONCLUSIVE, jadi tidak menurunkan recall di kamera full-body yang sudah benar setupnya.

## Implementation
- Tambah pure helper `is_full_body_bbox(person_bbox, frame_shape, min_height_ratio=0.6, edge_margin_px=20)` di module baru `detection_filters.py` — return True kalau person bbox tinggi >= 60% frame DAN bbox bottom dalam edge_margin dari frame bottom (kaki visible). Tulis pytest property test (idempotent, edge cases overflow, frame_shape valid) di tests/test_detection_filters.py. Helper bersifat pure → bisa di-test tanpa cv2/YOLO mock.
- Tambah pure helper `should_publish_violation(streak_count, min_streak=5)` di module yang sama — temporal smoothing gate. Update `ServiceAPDBackend.process_camera_node` (line 801-810) untuk track `consecutive_violation_count` per node dan inkremen/reset per frame. Publish gate di line 846 (saat ini `if has_violation and (current_time - last_notification_time) > COOLDOWN_SECONDS`) jadi `if has_violation and should_publish_violation(streak) and (cooldown lewat)`. Default min_streak=5 frames (di 20 FPS = 0.25 detik) — bisa di-tune via config.py env baru `MIN_VIOLATION_STREAK`.
- Modifikasi `detect_ppe()` (line 623-696, terutama loop person 651-684): sebelum logic `missing.append`, panggil `is_full_body_bbox(person['bbox'], frame.shape)`. Kalau False (tidak conclusive), JANGAN inject default `not has_vest` / `not has_helmet`; cuma append violation kalau ada `explicit_no_helmet` / `explicit_no_vest` (kelas eksplisit dari model). Person yang hanya kelihatan separuh tidak akan men-trigger pelanggaran palsu; person full-body tetap dicek seperti sekarang. Tambah debug log Indonesian-friendly: `logger.debug(f'[detect] person bbox not full-body, conclusive only: explicit_violations={explicit_no_helmet or explicit_no_vest}')`.
- Aktifkan FP16 inference di `load_model()` (line 369-390): setelah `self.model = YOLO(PPE_MODEL_PATH); self.model.to(self.device)` tambahkan `if self.device.startswith('cuda'): self.model.model.half(); self.person_model.model.half()`. Lalu di `detect_ppe()` line 627-628 tambah arg `half=True` ke kedua call. Add config flag `USE_FP16` di config.py (default True bila CUDA available, False kalau CPU) supaya bisa di-toggle untuk debug. Verifikasi: print FPS sebelum/sesudah di sample log selama 30 detik.
- Implementasi adaptive frame skip — ganti static `DETECT_EVERY_N = 1/3` di line 809 dengan `AdaptiveSkip` class kecil yang track inference latency rolling avg (deque size 30). Kalau avg latency > target (mis 50ms), naikkan skip; kalau < target/2, turunkan. Bound 1-5. Tetap pure helper (terima latency_sample, return new_n) supaya bisa di-pytest. Tetap honor `last_annotated/last_safe/last_violations` carryover untuk frame yang di-skip (line 838-840), TIDAK boleh trigger violation streak inkremen di frame yang di-skip — kalau tidak smoothing jadi rusak.
- Fix bug laten: wire `/api/settings` jadi dibaca Python saat startup. Tambah `fetch_dashboard_settings()` di ServiceAPDBackend.py mirip pattern `fetch_nodes_from_dashboard()` (line ~107). Override `CONFIDENCE_THRESHOLD` dan `PERSON_CONFIDENCE_THRESHOLD` dari config.py kalau response punya nilai valid. Refresh tiap N menit (mis. 5) supaya operator bisa adjust live tanpa restart. Atau alternatif: tambah disclaimer note di UI settings 'Restart backend untuk apply' kalau live-reload terlalu invasif. Diskusi opsi mana yang dipilih sebelum implement.
- Fix safe-bbox drawing: di `detect_ppe()` line 682-684 (else branch saat `not missing`), tambah `cv2.rectangle(annotated_frame, (px1, py1), (px2, py2), COLOR_SAFE, 3)` + label hijau 'APD OK'. Symmetric dengan path violation di line 677-681. Visible improvement langsung tanpa cost performance.
- Tambah dokumentasi panduan pemasangan kamera di docs/PBL-PENGOLAHAN-CITRA.md (extend existing line 222-232) atau buat docs/CAMERA-SETUP.md baru: angle, jarak, ketinggian, syarat full-body framing, contoh good/bad placement, hubungannya dengan `is_full_body_bbox` threshold default. Cantumkan trade-off close-up (high recall pose tapi false positive) vs full-body (less FP, mungkin miss kalau orang membungkuk).
- Tulis pytest test `tests/test_detection_filters.py` dengan: (a) property test fast-check style untuk `is_full_body_bbox` — bbox di tengah dengan tinggi 80% frame → True, bbox 30% tinggi → False, bbox menyentuh frame top tapi pendek → False; (b) PBT untuk `should_publish_violation` — streak < min → False, streak >= min → True, streak monoton (tidak boleh decrease tanpa reset); (c) PBT untuk `AdaptiveSkip` — output bounded 1..5, monotonic dengan tren latency. Jalankan `pytest tests` di root project (sesuai AGENTS.md verification rule).
- Smoke test E2E di hardware: jalankan ServiceAPDBackend.py + dashboard + ESP32. Verifikasi dengan log + visual: (1) orang full-body pakai vest+helm → green box drawn, no violation; (2) orang full-body tanpa vest → red box, violation publish setelah ~5 frame; (3) orang separuh badan kepala-dada → no violation publish (log debug `not full-body, conclusive only`); (4) FPS sebelum vs sesudah FP16 di log (target naik 1.5-2×); (5) settings slider di dashboard → ubah threshold → tunggu 5 menit → verifikasi nilai aktif di backend log. Update follow-ups.md dengan hasil hardware test.
